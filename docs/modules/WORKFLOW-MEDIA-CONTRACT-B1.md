# L3-B1：工作流扩展媒体声明与执行边界

2026-11-06，开工基线 5bfa4c3。在 `feature/workflow-media-contract` 分支实施，基于 UI 分支叠加，不修改其历史、不合并 main。执行合同第 45 节允许后端扩展独立交付；这不是新的 UI 重建分支。

## 审计结论与分包

现有 WorkflowInput、字段 Schema、目录不可变修订与 Provider 检查可复用；Job snapshot.image、uploadImage、单 resultDescriptor、归档和 Board first_frame 仍是单输入/单产物。直接添加媒体选择器会造成遗漏，不能以单首帧 I2V 声称 R2V 已完成。

B1 先交付可管理、持久化、检查的扩展输入/输出声明和执行拒绝边界。B2 再扩展固定媒体输入快照、Provider 上传/注入及 Worker 恢复；B3 接画布槽位、素材排序及真实模型验收。各包独立测试，B1 不向用户开放伪执行入口。

## 本包修改与兼容

| 层 | 修改及复用 |
|---|---|
| DB | 无新表、无迁移。扩展原 definitionJson，原不可变修订与 Job 历史不改写 |
| 合同 | WorkflowInput 增加可选 mediaSchema（studio.workflow-media.v1）。inputs 表示原首帧之外的扩展媒体槽位；outputs 表示原主输出之外的扩展结果 |
| 输入 | 自动 UUID、显示名、图片/视频/音频、用途、node/input、必填与缺失处理；有序列表就是槽位顺序。必填缺失报错，可选缺失声明为空值，不沿用导入图中的本机文件路径 |
| 输出 | 自动 UUID、显示名、媒体类型、node/field、预览/中间角色及是否多项；原 output 继续唯一主输出，避免双重配置 |
| API | 原工作流创建/修订/恢复/definition 接口兼容扩展；config 增加去技术目标的媒体声明摘要和可执行状态，不泄露图/路径/凭据 |
| 校验 | 输入只能绑定现有文件名常量，禁止与正负词、首帧、参数或公开字段争用目标；ID、目标不可重复。远端校验对应 upload 类型标记，输出须是真实 output_node；不靠节点名称猜能力 |
| 执行 | 无扩展声明的旧工作流保持原行为；只要声明扩展输入或输出，当前 Job 统一返回 WORKFLOW_MEDIA_UNSUPPORTED，不创建任务、不静默忽略、不消耗 GPU。所有入口共用 GenerationService 门禁 |
| UI | 工作流中心配置扩展媒体声明并保存固定修订；明确显示“已保存声明，执行尚未接通”。画布、通用生成、试跑不允许提交此类工作流 |
| 权限 | 原项目/工作区配置权限、RBAC、CAS、幂等、试跑隔离保持不变；不放开跨项目媒体访问。共享不依赖本包，不通过复制绕过授权 |

本包不修改 ComfyUI 环境、不下载权重、不复制参考项目源码，不宣称音视频上传或多输出归档已实现。Optional 空值在后续具体节点/Provider 支持与试跑前不可执行。

## 验收

- 单元验证有界 Schema、非法目标/类型/重复/冲突、缺失规则及旧图兼容。
- 隔离 API + Mock 验证创建、读取、修订/旧版本不变、远端元数据不匹配、只读摘要及原队列拒绝（含试跑/项目/Board），不产生远端提交。
- 浏览器验证声明编辑/排序/删除、失败保留、固定版本读回和明确不可执行状态；旧单首帧完整创作回归。
- 构建、类型、格式、相关 API 与浏览器套件通过后，在 IMPLEMENTATION-STATUS 记录实际证据与尚未完成的 B2/B3。
