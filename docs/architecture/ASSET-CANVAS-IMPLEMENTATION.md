# 项目资产、多画布、多模态：当前差异与最小路线

2026-11-06，以 8434529 及本轮实际代码为基线。补充方案作为产品方向，具体能力以代码和真实工作流验收为准；最新去留决定见 [ADR-012](../ADR-012-remove-retired-creation-ui.md)。

| 方案内容 | 实际情况与取舍 |
|---|---|
| 一项目多画布、共享项目资源 | 原 Board/Revision 已支持多张；本轮补切换/新建、独立历史、按用户记住上次打开；三张画布共用同一固定角色和媒体已验收 |
| 不要求剧本/镜头/Artifact | L1 已解除；本轮直接删除旧创作页面与分支，不再维护兼容菜单 |
| 资产与媒体 | 四类语义资产/修订、图/视频/音频和 Local 已有；本轮继续直接使用；风格实体、角色多媒体角色组合、独立提示词库待做 |
| 普通提示词库 | 当前只有自由输入、任务实际词快照及复用；旧 Shot 编译器不是 Prompt Library，不复用其强绑定 API |
| 有名称/类型的输入端口 | 当前只有标量公开字段和单首帧；Board 连线仍是注释，不能把现有连线默认为执行输入 |
| 多参考、多输出 | 未实现。保留原 Job/Worker，先建立显式输入/输出 Schema，按真实工作流扩展；不是用 I2V 的 imageVersionId 塞多个文件 |
| 项目/指定用户共享 | 未实现；当前项目隔离保留。需统一授权贯穿列表、详情、预览、原件、引用解析、Worker 提交前、导出和撤销 |
| H3 能力 | 保留 T2I/T2V/I2V 合同；官方存在 T2I 模板，不能因文字判断删掉图片生成。R2V 是独立工作流，不以单首帧验收替代 |
| 旧项目、Shot、Take、历史结果 | 数据和引用解析仍有效；旧编辑页面删除，后端读取与来源/导出依赖继续回归。无破坏性迁移 |
| 新一套队列、仓库、完整 ComfyUI 编辑器、NLE/Agent/插件市场 | 不引入 |

## 后续包按依赖实施

| 顺序 | 修改范围 | 最小交付与验收 |
|---|---|---|
| L2-B 提示词库 | 新项目级文本身份/不可变修订，复用 RBAC/CAS/审计模式；API prompt-library 独立于 Shot；Web 库与生成窗口/画布便签入口 | 标题/正负词/标签/来源保存、搜索、复制、固定版本应用到任意同项目画布；修订后旧 Job 词不变。先普通文本，不做变量语言/AI 自动改写 |
| L2-C 正式执行节点 | Board 合同新增 schemaVersion，读取 v1 为原注释图；Workflow/Prompt/Result 节点、命名端口与 input_binding；同一 Job 增加明确 Board 修订上下文 | 首先 TEXT+单 IMAGE→现有 I2V；连线与直接选素材同合同，必填/类型/重复/自循环/超量校验；显式点击才执行，恢复不重复创建结果 |
| L3-A 授权引用 | 统一 ResourceAccess 服务与最小授权表，Project/User 接收方、View/Use/Export/Manage；既有资源项目归属保留 | 默认私有；同工作区指定共享；固定版本；预览/下载分别受权；提交前重查 Use；撤销显示受限占位，不删已生成作品。先端到端权限测试，再开放 UI |
| L3-B 多模态合同 | Workflow 输入/输出声明、Provider 上传/结果解析、Job 快照、资产来源关联、UI 端口与排序 | 按用户已就绪的工作流逐一支持 IMAGE[]/VIDEO/AUDIO/多输出，准确传入编号与端口；共享素材不能靠临时复制绕过授权；Ref2VA 实机需用户模型就绪后单独验收 |
| L4 通用交付与资产扩展 | 项目媒体选择打包、manifest、提示词版本/角色位、音频标签和来源 | 无 Shot 交付原件与元数据；按真实需求加批量、共享/审核，不恢复旧剧本生产前置 |

每包开工前写具体表/接口/组件/失败处理合同。不因这份路线预建一批空服务；不把全部共享权限或任意图执行塞入清理包。单工作区普通用户、管理员设置入口、画布搜索/归档仍可逐步优化，当前不宣称全部完成。
