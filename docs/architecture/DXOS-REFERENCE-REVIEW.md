# DX OS 本地功能研究与采用边界

2026-11-06，Pullet 基线 e0228fd。参考用户提供的 `D:/DXOS-Portable/analysis/01-系统架构.md` 至 `05-复刻与集成指南.md`，重点研究画布、ComfyUI 与集成契约。这里记录的是本地分析文档所描述的行为，并非已经运行或独立验证 DX OS 的全部能力。无需重复克隆，也没有执行 EXE、复制压缩产物或读取运行数据/凭据。

最高要求为[执行合同](../PRODUCT-EXECUTION-CONTRACT.md)。参考文档中的“复刻必须”、工期、框架建议和原样部署方案不是 Pullet 的实施指令。

| 参考行为 | Pullet 当前实际 | 决定 |
|---|---|---|
| 围绕画布与资源形成连续工作空间 | 项目直达 Board，但正式 Board 仍是全屏弹窗 | P0 改为普通项目主视图，继续复用现有控制器，不引入 OS 窗口系统 |
| 媒体成为画布卡片主要内容，工具就近出现 | 正式大图节点、工具轨、浮动生成与可收起图库已接真实接口 | P0 持续打磨正式组件；隔离原型冻结，不建立第二生产画布 |
| 输入、当前结果、历史分别存放 | 具名输入和任务候选已有独立合同，结果显式加入画布/素材库 | 保持；严禁结果自动替换输入，任务继续固定原提示词和媒体版本 |
| 工作流封装 fields/outputs/capabilities，字段绑定 nodeId/input，媒体有 role/slot | 已有 API JSON、节点图、标量映射、不可变修订和单首帧执行 | P1 扩展已有合同，声明与实际校验一致，不从名称猜能力；多图/视频/音频及多输出尚未实现 |
| 资源通过稳定文件 ID 在工具间复用 | 已有 MediaAsset/Version/Storage、固定引用和同项目跨画布复用 | 保留原稳定 ID 与版本；不迁移 DX OS 文件系统，不重复复制媒体 |
| 多实例与运行快照 | 原 Job/Worker、实例授权、自动/手动调度和恢复已存在 | 复用；真实双机仍待单独验证，不启动/安装参考项目的模型环境 |
| 私有资源、指定授权、撤销 | 当前项目授权存在，跨项目/指定用户共享尚未完成 | P1 独立 DB/API 工作包，预览/下载/生成/导出均需服务端授权 |
| 节点插件、宿主、Bridge、环境安装、Agent 编排 | 不属于当前 Web 创作主线 | 暂不引入；保留已有可插拔 Provider/Storage，不执行动态第三方脚本 |
| 增量 sync、自动合并卡片 | 原 Board 已有不可变修订、CAS 与冲突保留草稿 | 保持原合同；不为参考项目改写并发协议 |
| 删卡后按引用软删文件 | 媒体有跨画布、历史与任务引用 | 不采用；删节点不等于删除媒体 |
| 原样部署第三方前端 bundle、建立兼容后端 | 已有 NestJS/React/Drizzle/SQLite 与大量已验收能力 | 不采用；独立实现交互，不复制闭源 JS/CSS/WASM/图标/壁纸/品牌 |

MiniMax H3 参考预设中的媒体槽位数量只代表该 JSON 配置，不作为全平台或全部模型的上限。单首帧 I2V 已有证据不代表 R2V 已支持。能力必须来自已保存、已验证的工作流输入输出。
