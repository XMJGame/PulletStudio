# 一、产品方向正式调整

## 1.1 核心决定

Pullet Studio 不再以“剧本管理 → 自动分镜 → 镜头卡 → 生成素材”的固定线性流程作为产品主线。

新的产品方向确定为：

**Pullet Studio：资产驱动、工作流驱动、无限画布驱动的 AI 影视创作与素材生产平台。**

它的主要职责是帮助个人和团队：

1. 管理和复用角色、场景、道具、风格、声音、音乐等创作资产。
2. 利用无限画布组织参考素材、提示词和生成关系。
3. 将 ComfyUI 工作流及其他合法 AI 服务封装为可复用的生成工具。
4. 从参考图、角色和场景等素材生成图片、视频和音频。
5. 管理多个生成版本，进行比较、筛选、复用和导出。
6. 在多人协作时保证项目隔离、资产权限和结果可追溯。
7. 使用本地多 GPU 工作站、NAS 和按需接入的云端 API 进行素材生产。

## 1.2 我们不解决什么问题

Pullet Studio 现阶段不负责完整自动编剧，也不承担专业后期制作。

剧本、旁白稿、广告创意、镜头描述、分镜提示词，可以通过 ChatGPT、Codex、其他智能体或人工方式在外部完成。

这些内容可以粘贴、上传或引用到 Pullet Studio，但不要求必须先经过它的剧本解析与自动分镜系统。

**外部负责内容创意，Pullet Studio 负责资产组织、素材生成和生产管理。**

未来如果 AI Agent 能够稳定处理剧本与分镜，可以作为可选入口接入，不能重新成为所有用户必须经过的前置流程。

## 1.3 首要设计原则

- 用户可以创建空项目，直接开始生成素材。
- 不强制创建剧本。
- 不强制创建正式镜头。
- 不强制创建分镜或故事结构。
- 不强制使用 Pullet Studio 内置 AI 编写提示词。
- 不强制使用特定 AI 模型或 ComfyUI 工作流。
- 不强制先通过多人审批才能进行个人创作。
- 必须允许从已有图片、视频、音频和提示词继续创作。
- 生成结果能够作为资产再次参与后续生成。
- 技术复杂度尽量留在工作流配置层，不暴露给普通创作者。

# 二、目标用户与应用场景

平台不是单一的神话视频制作工具，应支持多种 AI 影视内容。

## 2.1 中国神话、历史故事和知识类旁白长视频

典型流程：

外部完成故事研究、旁白文案和镜头提示词。

在 Pullet Studio 中：

1. 创建项目。
2. 建立统一的视觉风格资产。
3. 创建角色设定，例如盘古、女娲等。
4. 创建场景资产，例如混沌空间、远古山川、神殿。
5. 根据提示词生成角色设定图和场景图。
6. 结合角色、场景和提示词生成镜头首帧。
7. 通过图生视频或其他视频工作流生成片段。
8. 比较和选择满意版本。
9. 管理旁白、BGM 和环境音素材。
10. 将视频片段及声音素材导出到剪映、DaVinci Resolve、Premiere 等软件完成后期。

这种场景以旁白为主，不强制为每个角色创建音色，也不要求生成角色口型。

## 2.2 AI 短剧

短剧重点是人物一致性、场景连续性、多角色互动与台词声音。

需要支持：

- 角色定妆图与多视图。
- 同一角色的服装、发型及造型版本。
- 多角色参考输入。
- 不同角色的音色绑定。
- 场景和道具复用。
- 单镜头或连续片段生成。
- 有台词和无台词两种生成方式。
- 角色、场景、首尾帧等固定资产版本。
- 候选片段筛选和导出。

不要求平台自动完成整部短剧的剧本和所有镜头。

## 2.3 AI 广告片

广告更关注产品形象、视觉风格、创意变化和素材生产效率。

需要支持：

- 产品/道具资产。
- 品牌视觉风格。
- 产品参考图。
- 场景组合。
- 图像修改与变体。
- 文生图、图生图、图生视频。
- 视频放大与修复。
- 不同广告方案对比。
- 高质量原始素材导出。

不能让广告用户必须先创建人物或镜头卡。

## 2.4 AI 长视频和电影

长项目与短项目共用底层系统。

主要差别是：

- 资产规模更大。
- 版本更多。
- 参与人员更多。
- 对连续性和归档要求更高。
- 可能需要按章节、场次、序列或制作批次组织素材。

因此建议用灵活的项目集合、分组和标签组织内容，不为电影、广告、短剧分别开发独立业务系统。

# 三、产品信息架构

建议将正式产品聚焦为以下主要模块。

## 3.1 项目空间

项目空间负责组织资产、画布、任务和导出。

支持：

- 项目名称和描述。
- 项目视觉风格或默认风格资产。
- 项目成员与权限。
- 一个项目下的多个创作画布。
- 可选的章节、场次、序列或自定义分组。
- 项目内资产和结果检索。
- 项目素材交付。

项目不再强制建立“剧本 → 分镜 → 镜头”层级。

已有制作单元和镜头结构可以作为兼容的高级组织方式，但新用户应能完全跳过。

## 3.2 资产中心

管理所有可以复用的创作对象及其媒体版本。

## 3.3 创作画布

以 React Flow 为基础，实现自由素材组合、提示词输入、工作流生成和结果比较。

## 3.4 工作流中心

管理 ComfyUI 工作流、输入输出映射、模型依赖和模板版本。

## 3.5 任务与结果中心

负责生成任务、进度、错误、重试、候选管理与统一归档。

## 3.6 系统设置

主要提供：

- 用户与团队管理。
- ComfyUI 实例管理。
- 模型和工作流能力检查。
- 存储配置。
- 生成资源和使用权限。
- 后续云端 Provider 配置。

普通创作者不应该频繁进入系统设置。

# 四、资产中心详细规划

资产库是新版产品的核心。

但必须区分两个概念：

**媒体文件：** 图片、视频、音频等真实文件及其媒体版本。

**语义资产：** 角色、场景、道具、声音身份等带有描述、关系和修订历史的业务对象。

一个角色可以关联多张图片；同一张图片也可以被多个画布引用。

不要把资产库简单实现成一个按文件夹分类的文件管理器。

## 4.1 角色资产 Character

建议支持：

- 名称和别名。
- 角色描述。
- 外观与体貌描述。
- 发型、服装、配饰等视觉特征。
- 风格关键词。
- 统一提示词或外部提示词引用。
- 主参考图。
- 角色设定图。
- 全身图。
- 正面、侧面、背面多视图。
- 表情参考。
- 服装与造型变体。
- 动作或姿态参考。
- 可选音色绑定。
- 版本历史。

这里的年龄、性别等可以作为创作者自愿填写的设定字段，不应该成为创建角色的必填条件。

角色需要有一个明确的**当前选用形象版本**，供生成时选择。

但历史生成任务必须固定引用当时使用的版本，不能跟随角色最新形象自动改变。

### 角色三视图工作流

这是重要能力，但不应硬编码为只能使用某一种模型。

推荐标准输入：

- 角色描述或已有参考图。
- 风格。
- 服装设定。
- 可选随机种子及模型参数。

标准输出：

- 正面视图。
- 侧面视图。
- 背面视图。
- 可选全身参考或多视图拼图。

系统可以支持一次生成三视图拼图，也可以使用多次生成并逐张校验的工作流。

需要注意：三视图只是角色一致性的参考，不保证不同 AI 模型能够严格保持身份、比例和细节一致。

要保留人工检查、选用版本和重新生成的操作。

**角色三视图是一个工作流模板，不是必须重新开发的专用推理引擎。**

## 4.2 场景资产 Scene / Location

支持：

- 场景名称。
- 场景描述。
- 主场景图。
- 不同机位参考。
- 日景和夜景变体。
- 环境、建筑和布景特征。
- 风格及色彩设定。
- 相关道具。
- 多张场景参考图。
- 场景版本。

一个场景可以跨多个项目使用，但跨项目共享必须遵守授权边界。

## 4.3 道具与产品资产 Prop / Product

统一支持影视道具和广告产品。

包括：

- 名称与描述。
- 主参考图。
- 不同角度的参考。
- 材质、颜色和外观要点。
- 可选尺寸与比例描述。
- 品牌或视觉规范。
- 版本和生成来源。

不需要为商业广告单独建立第二套产品素材系统。

## 4.4 风格资产 Style

风格资产用于统一整个项目的视觉表达。

包括：

- 风格名称。
- 风格描述。
- 示例图片。
- 正向关键词。
- 负向约束。
- 色彩、光照、材质与摄影语言。
- 推荐的工作流或模型配置。
- 版本与适用范围。

例如中国神话古朴风、写实电影风、现代广告风等。

风格必须能够作为画布生成输入，而不是只作为项目说明。

## 4.5 音色资产 Voice Profile

建议与真实音频文件分开建模。

音色资产描述一个可复用的声音身份，例如：

- 旁白音色。
- 角色配音音色。
- 声音风格。
- 语速、情绪或发声特点。
- 可播放的试听样本。
- 已授权的声音来源。
- 可用的 TTS Provider 或工作流配置。

音色不等于某段台词录音。

神话长视频可以只设置一个旁白音色；短剧才需要按角色绑定音色。

涉及真实人物声音克隆时，必须保存授权与使用范围，不能默认为所有声音样本都可以克隆或商业使用。

## 4.6 音效 SFX、背景音乐 BGM 与音频媒体

建议底层共用媒体存储，语义分类区分：

- 环境音。
- 动作音效。
- 特效音。
- 旁白录音。
- 角色对白。
- 背景音乐。
- 其他音频。

需要支持：

- 试听。
- 时长及格式。
- 标签。
- 来源。
- 许可与使用范围。
- 版本。
- 导出。

首版可以先完成导入、管理、预览和导出，不强制立即支持音频 AI 生成。

## 4.7 提示词资产与模板

提示词是重要的生产素材，但不能与工作流定义混为一谈。

支持：

- 外部粘贴的完整提示词。
- 正向词、负向词。
- 角色与风格描述引用。
- 提示词修订。
- 推荐模型或工作流。
- 可选的变量模板。
- 提示词来源说明。

允许直接粘贴 ChatGPT、Codex 或其他工具生成的内容。

**不要求平台必须重新编写提示词。**

初期只需要可靠保存、复制、引用和版本管理，不必开发复杂的 AI 提示词代理。

## 4.8 资产设计原则

所有关键资产都要支持：

- 来源文件不被生成操作直接覆盖。
- 新结果先作为候选版本。
- 由用户明确选择采用版本。
- 版本可追溯。
- 跨画布引用。
- 权限检查。
- 原件下载与导出。

不要为每种资产重新开发一套相似的数据库、上传器和版本服务。

应充分复用现有 Assets、MediaVersion、Storage 与权限体系。

# 五、无限画布详细规划

无限画布是主要创作入口。

**它不是专业剪辑时间线，也不是把 ComfyUI 全部技术节点原样搬进浏览器。**

## 5.1 核心节点类型

### 资产节点

- 角色
- 场景
- 道具/产品
- 风格
- 音色
- 音频
- 图片
- 视频

### 创作输入节点

- 提示词
- 文本说明
- 图片参考
- 视频参考
- 音频参考
- 可选参数

### 生成节点

由工作流中心创建的可复用生成节点，例如：

- 文生图
- 图生图
- 角色多视图
- 场景图
- 多角色合成
- 图生视频
- 视频延长
- 视频修复
- 视频放大
- 音频生成
- 旁白生成

实际是否可用，取决于对应工作流或 Provider 是否已验证。

不应在前端假设所有模型都支持全部能力。

### 结果节点

- 生成图片
- 生成视频
- 生成音频
- 候选集合
- 采用版本

### 组织节点

- 便签
- 分组
- 标签
- 可选制作序列或素材集合

## 5.2 画布必须支持的核心操作

- 拖入正式资产。
- 上传外部参考素材。
- 创建和编辑提示词。
- 选择工作流。
- 将参考素材连接到工作流的对应输入端口。
- 填写模型参数。
- 创建生成任务。
- 显示任务状态。
- 生成结果回到画布。
- 放大预览、比较和筛选。
- 将满意结果保存为资产版本。
- 使用已有结果继续图生图、图生视频等操作。
- 将素材导出。
- 保存、重新打开和恢复画布。

生成任务不能因为浏览器关闭而停止。

## 5.3 连线的含义必须明确

画布将出现两种不同的关系：

**创作关联：** 表示角色、场景、参考素材或其他内容之间的组织关系。

**生成依赖：** 表示某个工作流实际需要使用的输入数据。

两者不能混淆。

例如角色节点连接场景节点，不代表后台自动执行生成。

只有明确提交生成任务，才调用模型。

生成依赖的输入类型需要验证，例如 IMAGE、VIDEO、AUDIO、TEXT 等。不能把不兼容的输入静默发送给工作流。

## 5.4 保持普通用户体验简单

用户在画布上使用生成节点时，默认只需要看到：

- 工作流名称。
- 所需输入素材。
- 提示词。
- 必要参数。
- 生成按钮。
- 生成状态和结果。

高级参数折叠。

ComfyUI 的模型加载器、采样器、VAE、节点 ID 和服务器地址等细节只在工作流中心展示。

## 5.5 可选的镜头组织

不要强制所有生成结果都属于正式 Shot。

但要允许用户把图片或视频归入某个“镜头/片段/序列”集合，方便长视频生产。

一个项目可以有镜头组织，也可以完全没有。

画布用户应当能够：

**创建项目 → 放入提示词 → 生成图片 → 生成视频 → 保存结果**

而不需要先创建虚构的正式镜头。

# 六、工作流中心详细规划

工作流中心是技术人员配置模型能力的入口。

## 6.1 ComfyUI 工作流导入

主要采用单个 **API Format JSON**。

导入后：

1. 解析节点 ID、类型、输入和依赖。
2. 自动生成只读技术节点图。
3. 识别可配置字段。
4. 使用 ComfyUI `/object_info` 辅助校验。
5. 管理员确认需要暴露的参数。
6. 标记输入与输出类型。
7. 保存工作流版本。
8. 通过测试后提供给创作画布使用。

不强制上传普通 UI Workflow JSON。

## 6.2 参数映射

需要逐步支持：

- 文本与提示词。
- 数值。
- 布尔值。
- 枚举。
- 图片输入。
- 多张参考图片。
- 视频输入。
- 音频输入。
- Seed、分辨率及其他模型专用参数。

不同工作流支持不同输入。

不得仅依靠字段名称猜测其类型并视为已经验证。

## 6.3 工作流输出

工作流可能输出：

- 单张图片。
- 多张图片。
- 视频。
- 音频。
- 图片与视频。
- 视频与音频。

不能长期将整个工作流系统限制为单个图片或单个视频输出。

但应依据真实工作流逐步扩展，不为了理论兼容开发无限通用的图执行器。

## 6.4 工作流发布

保留管理员配置、版本历史和团队权限。

但应区分：

**个人探索：** 已保存、可在授权范围内测试的工作流。

**团队正式使用：** 经过验证并明确发布的工作流。

个人创作不应被复杂审批流程阻塞。

对多人生产或重要项目，可以保留试跑证据和正式发布门禁。

管理员试跑最好允许直接使用临时或现有测试素材，而不是强制先创建正式镜头。

## 6.5 预置工作流

Pullet Studio 可以提供分类和配置模板，例如：

- 角色定妆。
- 角色三视图。
- 场景概念。
- 多角色构图。
- 文生图。
- 图生图。
- 图生视频。
- 首尾帧视频。
- 视频增强。
- 音频生成。

但预置模板必须标注其模型依赖、适用条件和验证状态。

不要把未安装、未测试的工作流显示为开箱即用。

# 七、生成任务和多实例调度

## 7.1 保留当前实现基础

继续保留现有：

- NestJS Generation Service。
- 持久化生成任务。
- 独立 Worker。
- 任务恢复。
- ComfyUI 原生 API。
- 工作流版本。
- 媒体归档。
- 实例池。
- 自动和手动路由。

V1 仍只使用 ComfyUI 原生 `POST /prompt`，暂不依赖 ComfyUI-Distributed 专用 API。

现有多实例实现已通过 Mock 验证，但真实双机并行执行和恢复仍需单独验收。

## 7.2 必须解除生成任务对 Shot 的强制依赖

这是本次调整最重要的技术问题之一。

当前部分 Generation Job、试跑、审批和结果流程依赖正式 Shot。

新的产品需要支持不同来源的生成请求：

- 从画布直接生成。
- 从某个角色资产生成。
- 从场景资产生成。
- 从已有图片继续生成。
- 从正式镜头生成。
- 从工作流中心独立试跑。

因此需要设计统一的生成上下文。

生成任务应当始终归属项目或工作区，但不必须归属镜头。

建议在现有 Job 体系上增加或调整上下文，例如：

`project / board / asset / shot / workflow_trial`

具体数据库结构、兼容路径和迁移方式由实施者核对现有代码后决定。

**不要为了兼容旧接口而偷偷创建一个用户看不见的虚构镜头。**

旧镜头任务和历史 Take 必须继续可读取、可恢复和可导出。

## 7.3 任务快照

每次实际提交应保存：

- 项目与发起人。
- 工作流固定版本。
- 输入参数。
- 外部或已保存的提示词快照。
- 输入资产与媒体固定版本。
- 执行实例。
- ComfyUI Prompt ID。
- 输出媒体。
- 状态与错误。
- 使用的 Provider 信息。

同一角色后来修改外观，不应该改变过去生成任务的历史来源。

## 7.4 多实例调度

默认自动选择满足要求的实例。

高级用户可以指定具体机器。

能力匹配基于：

- 健康状态。
- 模型和节点依赖。
- 队列与容量。
- 管理员配置。
- 权限范围。

实例状态尽量由后台自动维护，不要求普通用户反复手动检查。

需要特别注意多机输入素材上传、任务响应丢失后的核对，以及同一任务不被重复提交。

# 八、生成结果与候选管理

这是非常重要的产品模块。

## 8.1 结果不等于正式资产

生成成功后，先形成可追溯的结果记录。

用户可以：

- 预览。
- 比较。
- 标记喜欢。
- 重新生成。
- 继续编辑或作为下游输入。
- 明确保存为资产版本。
- 导出。

普通创作者不应该为了保存一张图片而经历完整的影视审批流程。

## 8.2 轻量选择与正式审核分离

推荐区分：

**个人候选选择**

- 喜欢。
- 不采用。
- 采用为当前版本。

**团队正式审核**

- 提交审核。
- 批准或拒绝。
- 选用正式版本。
- 保留审核记录。

正式审核应是有权限、有明确需求时使用的能力，不是所有生成操作的必经步骤。

已有 Take 系统优先复用，但不要让所有图片、声音和参考图都必须成为 Shot Take。

## 8.3 结果继续创作

这是无限画布的重要价值：

- 生成角色图 → 生成多视图。
- 生成场景图 → 修改视角。
- 角色 + 场景 → 生成构图。
- 构图 → 生成视频。
- 视频 → 放大、修复或延长。
- 音频 → 作为视频或最终交付参考。

每次操作都生成新的结果或修订，不覆盖原始媒体。

# 九、导入、导出与外部工具协作

## 9.1 外部输入

至少支持：

- 图片上传。
- 视频上传。
- 音频上传。
- 提示词粘贴。
- TXT / Markdown 文本导入。
- ComfyUI API JSON。
- 现有资产版本引用。

可以后续支持 CSV / JSON 批量提示词列表，但不需要立刻开发复杂的自动剧本解析。

## 9.2 输出交付

默认提供：

- 单个图片、视频或音频原件下载。
- 多选素材导出。
- 按项目或自定义集合打包。
- 生成来源与必要元数据。
- 可供外部剪辑软件使用的命名规范。

正式交付包可根据实际需要包含素材清单和版本信息。

SRT、OTIO、FCPXML 等格式作为按需增强，不阻塞主流程。

## 9.3 不开发完整专业后期工具

明确不开发：

- 完整多轨剪辑器。
- 转场编辑器。
- 逐帧关键帧系统。
- 专业调色。
- 专业混音台。
- 完整特效合成系统。

允许简单图片、视频、音频预览和低成本故事板连播，但不继续朝 NLE 方向扩展。

# 十、团队、权限与资产共享

现有 Workspace、Project RBAC、审计和版本控制应尽量保留。

建议角色区分：

- 管理员：维护服务器、存储、权限和正式工作流。
- 创作者：使用资产和工作流，创建画布、生成素材。
- 审核者：在需要时审核正式结果。
- 只读成员：浏览授权资产与项目结果。

具体权限继续复用现有服务。

跨项目资产共享可以后续扩展，但不能默认所有项目互相可读。

媒体预览、下载、生成结果和导出均必须受到服务端授权约束。

# 十一、对现有代码和历史功能的处理方式

这次是产品方向调整，不是从零重建。

现有仓库中已经实现了不少基础能力。

必须先做代码和数据审查，避免重复开发。

## 11.1 建议继续保留并复用

- 用户、项目和团队权限。
- 语义资产与媒体版本。
- Storage Provider。
- 正式创作画布。
- React Flow。
- Workflow Catalog / Revision。
- ComfyUI Provider。
- Generation Job / Worker。
- 多实例调度。
- 审计和必要的历史追溯。
- 结果审核和导出中的通用机制。

## 11.2 建议从主产品入口移出

- 以剧本为中心的固定生产流程。
- 强制自动分镜。
- 强制创建镜头卡。
- 不适合自由创作的复杂制作单元入口。
- 普通用户不需要理解的发布证据和底层配置页面。

这些功能可以先隐藏在兼容入口或高级区域。

## 11.3 暂时冻结，而不是直接删除

- 剧本导入。
- 剧本修订历史。
- 自动分镜分析。
- 分镜提案与采纳。
- 原有正式 Shot 生产链。
- 已有 Shot Take 审批数据。

必须保留历史项目和数据的读取能力。

先确认所有依赖关系，再决定未来是否彻底移除某些模块。

已经应用的数据库迁移绝不重写或删除。

## 11.4 需要重点重构的边界

- Generation Job 不再强制依赖 Shot。
- 工作流试跑不再强制依赖正式镜头。
- 创作画布能够直接启动通用生成任务。
- 结果可归入普通资产库，而不必须先成为 Shot Take。
- 资产与画布拥有明确、固定的媒体版本关系。
- 旧正式 Shot 路径继续兼容。

这些是产品调整带来的必要适配，不应被视为重新开发第二套 Generation 系统。

# 十二、暂不纳入核心产品的能力

以下功能应当有意后置：

- 自动编剧。
- 自动分镜及镜头语言推导。
- 一键生成完整电影。
- 复杂 AI Agent 多角色协作。
- 自动训练或微调角色模型。
- 自动下载、安装和维护所有 ComfyUI 模型。
- 自动修复任意第三方 ComfyUI 自定义节点。
- 内置专业视频剪辑器。
- 实时 CRDT 多人同步编辑。
- 插件市场。
- 完整 SaaS 商业计费。
- 同时维护多套后端技术栈。
- 为每种视频类型开发独立产品系统。

以后可以研究，但不能成为当前版本的必要交付条件。

# 十三、非功能要求

## 13.1 稳定性

- 长任务持久运行。
- 网络断开后安全恢复。
- 任务提交不确定时不能盲目重复发送。
- 输出文件经过必要校验。
- 资产版本不可静默覆盖。

## 13.2 性能

- 无限画布只加载当前可见媒体的必要预览。
- 原始视频不要直接全部加载到页面。
- 适当使用缩略图与懒加载。
- 大量节点时优先保持交互响应。
- 多 GPU 实例之间不能假设模型、节点和文件路径完全一致。

## 13.3 扩展性

- 模型能力通过 Workflow Profile / Provider 声明。
- 图片、视频、音频使用统一任务基础，但不强制相同输入输出结构。
- 新增一种 AI 模型尽量不修改创作画布核心代码。
- NAS、本地 SSD 与未来对象存储通过已有存储边界管理。

## 13.4 安全和版权

- 外部 API 密钥只保存在受控服务端。
- 不导入不可信的可执行代码。
- 不因导入 ComfyUI JSON 就自动安装第三方自定义节点。
- 声音克隆、背景音乐、参考图和第三方素材应支持授权来源记录。
- 不将违反服务条款的逆向代理当作正式生产依赖。

# 十四、如何决定先做什么、后做什么

**这里不要求 Codex 机械执行固定的开发排期。**

请先根据最新代码审查，判断哪些能力已有基础、哪些只缺界面、哪些涉及核心数据模型变化。

每一项候选工作从以下维度评估：

1. 是否直接服务“资产 → 画布 → 生成 → 结果 → 导出”主链路。
2. 是否阻塞当前用户真实使用。
3. 是否能够复用现有代码。
4. 是否会引入新的复杂业务系统。
5. 是否涉及旧数据和数据库迁移风险。
6. 是否能够通过实际 ComfyUI 工作流验证。
7. 是否需要用户提供模型、设备、账号或人工输入。
8. 是否会降低普通创作者的操作复杂度。

优先解决真正阻塞主链路的问题。

对于多个同等重要的任务，优先选择改动范围小、可测试、可回滚且可以复用已有服务的方案。

不要因为某功能容易开发，就提前增加大量不必要的功能。

也不要因为现有系统中某模块代码多，就认为它必须成为新产品的核心。

# 十五、最低可用产品验收场景

请围绕真实使用流程决定实施完成标准。

## 场景 A：无剧本、无镜头直接生成

1. 创建项目。
2. 打开空白创作画布。
3. 输入外部提示词。
4. 选择一个文生图工作流。
5. 生成图片。
6. 查看多个候选。
7. 将满意结果保存到资产库。
8. 从资产库重新打开该图片。

全过程不要求创建剧本或正式 Shot。

**这是本次方向调整的首要验收。**

## 场景 B：角色三视图与人物资产

1. 创建角色。
2. 输入外部人物描述或上传参考图。
3. 选择支持的角色多视图工作流。
4. 生成正面、侧面、背面等参考。
5. 对比结果。
6. 将选定图片关联到角色资产。
7. 保存固定版本。
8. 后续画布能够再次使用该角色。

## 场景 C：角色、场景结合生成视频

1. 从资产库拖入角色。
2. 拖入场景。
3. 输入镜头提示词。
4. 通过支持的工作流生成合成参考图或视频首帧。
5. 使用图生视频生成片段。
6. 选择结果。
7. 作为视频素材保存或导出。

不要求自动剪辑或生成完整电影。

## 场景 D：神话旁白内容

1. 外部完成旁白和提示词。
2. 导入风格、角色与场景资产。
3. 生成多张插图。
4. 将部分插图生成视频。
5. 导入旁白录音、BGM 和音效。
6. 整理、筛选并导出素材。

不强制为神话角色绑定音色。

## 场景 E：多 ComfyUI 实例

1. 管理员登记两个独立 ComfyUI 实例。
2. 正式工作流能够正确匹配实例能力。
3. 用户默认使用自动调度。
4. 高级用户可以手动选择机器。
5. 多个任务可以分别交由不同实例执行。
6. 输出结果能正确归档。
7. 网络异常和重启不会造成不可控的重复任务。

必须有真实设备验证；Mock 测试不能单独代表实机通过。

## 场景 F：历史数据兼容

1. 升级后的系统可以读取原有项目。
2. 旧剧本与正式 Shot 数据不丢失。
3. 旧生成记录与媒体结果仍可访问。
4. 新画布可以独立创建通用生成任务。
5. 已应用迁移及旧文件无需破坏性重建。

# 十七、产品最终原则

Pullet Studio 应该让创作者在自由选择内容创作方式的前提下，轻松使用 AI 完成素材生产。

一个人可以先写故事，也可以先生成角色；可以先设计场景，也可以直接上传图片生成视频。

用户不应该被一个预设的剧本和分镜流程束缚。

**核心体验应当是：**

**创建项目 → 建立或引用资产 → 在无限画布中组合输入 → 选择工作流生成 → 管理候选版本 → 保存与复用 → 导出。**

剧本、分镜、镜头卡和制作单元等已有能力可以作为可选的内容组织方式保留，但不再是产品的核心依赖。

**最终目标：把 Pullet Studio 做成面向 AI 短剧、广告片、神话长视频和 AI 电影的通用资产与素材生产平台。**

让工作流适应创作者，而不是让创作者适应工作流。
