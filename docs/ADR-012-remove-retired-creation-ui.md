# ADR-012 删除过时创作界面，统一项目资产与多画布

2026-11-06。用户在 V2 L1 后明确要求「该删除的删除，不要保留了」，覆盖 ADR-011 中继续保留兼容创作菜单的决定。补充方案见 [项目资产、多画布与多模态工作流](PROJECT-ASSETS-AND-MULTICANVAS.md)。

## 已采用

- 正式产品只使用项目资产库、项目任务和 Board/BoardRevision，不另建画布或队列。
- G0 独立实验彻底删除，包括 DOM/Flow 双实现、HTML、测试、构建和 CI 入口。
- 剧本/自动分镜/提案、制作结构/分集/镜头编辑、Shot 提示词编译、预演/旧交付等前端组件删除，不移到兼容目录，不再提供兼容菜单。
- 生成窗口只处理项目/画布通用输入；试跑只提供直接输入。旧类型、状态、无关查询、样式和专用浏览器 flow 一并清理。
- 多画布共享同一项目资产，可切换/新建，并按用户和项目记住上次画布；未保存草稿切换时明确处理。
- 下一批先做独立提示词库，再做有类型的生成端口/明确输入绑定；之后接入统一资源访问与共享，再按真实工作流扩展多媒体。

## 边界与事实修正

删除旧产品界面不等于删除用户作品。既有 Board 固定 Shot 引用、任务快照、媒体/审核和导出仍依赖 Production Core 的服务和表，保留这部分实际依赖及 API 测试；不改写旧 SQL、不清空数据库，也不让新页面继续加载旧编辑器。以后移除后端必须先证明没有引用或有独立历史读取路径，不能仅因文件名旧就删除。

新补充文档列出的 Shot 强制前置已在 L1 解决，不重复开发。个人探索不再被正式发布阻塞；管理员的工作流版本与试跑证据继续复用。

H3 不做基于名称的能力封锁：2026-11-06 已核对 [官方 T2I 模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_minimax_h3_t2i.json)，确有图像输出，不能从「主要用于视频」推出不能生图。保留已有 T2I 合同，按具体工作流绑定/节点检查和用户实际模型就绪情况开放，不声称已实机验证。

[官方 R2V 模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_minimax_h3_r2v.json)使用 Ref2VA 独立路径；I2V 的成功不能代替多参考验收。模板数量限制只能作为配置 Schema 输入，不写进通用画布，不推测连线顺序。输入图片、音频和视频按实际端口授权与冻结，音色元数据不能当音频文件。

共享继续默认拒绝跨项目访问。新增统一 ResourceAccess 前，不放开任何 `projectId` 检查，也不做一个可绕过预览/下载/Worker 的分享开关。本阶段不执行 GPU 任务、不下载模型、不复制上游受限代码。

本决策配合 [L2-A 合同](modules/CREATION-CLEANUP-L2A.md)和 [实施状态](IMPLEMENTATION-STATUS.md)执行，取代旧文件中「移至兼容入口」「保留 G0 实验」的当前建议；历史验收保留当时事实。
