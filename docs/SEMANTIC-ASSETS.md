# 资产库与镜头引用

2026-11-05，Phase C3/C4 基础范围。资产库管理的是人物、场景、道具、声音设定；项目素材管理的是物理文件。一个人物可有多张独立参考图，同一张已归档图片也可作为多个设定的参考。文件仍由原媒体模块保存，不复制或移动。

## 使用顺序

1. 在项目“制作结构”→“项目素材”导入所需图片或音频，核对实际文件。生成尚未接入时，也可导入外部工具手工制作的素材。
2. 打开“资产库”，选择人物、场景、道具或声音角色，填写名称、描述和类型设定；系统自动生成内部标识。
3. 选择参考素材、具体媒体版本和语义位置，点“添加媒体参考”。人物可有正面主锚点、侧面、背面、面部特写等独立图片；场景支持全景、平面布局与细节，道具支持多视角及细节；声音样本须为音频。每个修订最多10项。
4. 点“保存资产版本”。修改设定或增删参考文件都会追加新版本，已有镜头不会随之变化。历史版本可查看；要继续编辑，明确“载入最新资产”。当前所有资产版本都是草稿，尚无正式批准入口。
5. 打开镜头→“资产引用”，选择资产及明确修订，补充在镜头中的用途，加入引用列表后保存。每镜头最多20个实体、同一实体只选一个修订。没有完整制作卡时，先保存完整卡。保存引用会追加正式镜头/卡版本，旧卡不改。
6. 打开“镜头提示词”，预览或保存。编译会收集卡里固定的设定、用途与媒体参考，生成可复制文本和不可变输入快照。参考图缺失、正面/全景缺失、未批准或声音授权待核对均有警告；无模型能力与审批时仍为非生产就绪。

字段按类型区分：人物外观/服装/状态/连续性；场景布局/光线/状态/连续性；道具形体/尺度/材质/状态/连续性；声音语言/音色/使用范围/授权或同意状态。当前状态为文字设定，还不是 LookVariant、结构化连续性约束或自动检测。

## 版本与多人编辑

资产身份、实体修订、媒体版本、制作卡和 PromptArtifact 是不同的版本层级。参考“最新图片”或只填名称不构成固定引用。

- 上传媒体 v2 不替换实体修订中原来的媒体 v1。
- 修改人物为实体 v2 不替换镜头卡中的实体 v1。
- 镜头改用实体 v2 必须明确移除旧引用、选择新修订并保存新制作卡。
- 旧提示词快照保留旧文字和输入；资产/媒体有新版本时显示变化提示。重新编译仍采用卡里固定修订，不能自动选择最新资产。
- 资产库的“引用此资产的镜头”区分当前卡和历史卡；同一镜头可因多次修订出现多条历史记录。当前只显示镜头编号及卡版本，尚无直接跳转/批量更新入口。
- 两个窗口同时修改，只有符合当前版本的请求成功；另一份输入保留。点击“载入最新资产/引用”才替换本地内容。
- 创建及实体修订用持久化幂等键恢复失响应，重复提交返回同一结果。引用保存沿用镜头乐观锁，失响应时先载入最新引用核对；不盲目追加重复卡。

旧镜头的资产名称仍是文字备忘，不自动推断对应实体。旧完整卡接口未传 assetBindings 时保留已有固定引用，明确传空数组才清空；旧基本字段编辑、AI来源及历史卡继续保留。原有提示词/导出不回填或重写。

新生成的JSON、Markdown和CSV分镜导出均保留固定资产资料，不仅输出内部引用ID；Markdown增加“固定资产引用”，CSV末尾增加asset_references_json/asset_warnings_json两列。导出仍是文本快照，不含参考媒体字节或可重导入项目包。

## 权限与声音样本

项目读取权限允许看资产设定、修订及引用；项目编辑权限允许创建/追加草稿和绑定镜头。只读者和 Reviewer 不因此获得编辑权。回收站、成员移出与跨项目/工作区隔离沿用现有服务端授权。

声音样本的文件权限更严格：首次作为 voice_sample 引用后，仅该文件上传者、项目管理者、项目 Reviewer 或工作区管理者可播放/下载，且仍须能读取当前项目。普通项目成员可以查看声音文字设定及样本元数据，不能取得样本字节。样本从新修订移除后，历史引用仍维持该固定媒体版本的保护；不会通过清空当前资产解除限制。这个规则针对被引用的确切媒体版本，不对整个素材的将来版本自动分类。

添加样本前也检查文件读取权。若编辑者选择了其他成员上传的普通音频，保存为声音样本后可能需要管理者/审核者协助读取；界面事先说明权限规则。已经下载到用户设备的文件不受本应用控制；本包不提供细粒度声音授权名单或撤回已下载副本。

声音使用权/本人同意状态由用户填写，当前不等于平台已核验法律许可或本人身份。未配置任何外部声音服务，不发送音频或声纹。未知状态会警告，未来生成任务必须执行真实授权与版本批准门禁。声音与人物的独立版本关系、语言特定 Provider voice ID 绑定后续建设，当前不把供应商私有 ID 塞进通用实体。

## API 与数据

沿用 `/api/v1` 会话、CSRF、RBAC，资源ID由服务器分配：

- `GET/POST /projects/:id/entities`：kind 为 character/environment/prop/voice；列表20条，按创建时间/ID倒序，cursor 使用返回值。POST 为 `{kind,body}`，需 UUID Idempotency-Key。
- `GET /entities/:id`；`GET /entities/:id/revisions?before=版本`；`GET /entities/:id/revisions/:version`。
- `POST /entities/:id/revisions`：`{expectedVersion,body}`，需 UUID Idempotency-Key。body 包含 name、description、分类型 attributes 和完整 media 数组。媒体关联随修订整体保存，不提供可变的旧修订 media-bindings 接口；这是对蓝图建议路径的兼容性选择。
- `GET /entities/:id/impacted-shots?cursor=...`：20条，显示 cardVersion、entityVersion、current。
- `GET /shots/:id/asset-bindings` 返回完整卡编辑上下文；`POST` 为 `{expectedShotCardVersion,bindings:[{revisionId,purpose}]}`，成功追加卡。
- 原 `/shots/:id/card` 增加派生 assetReferences/assetWarnings；卡 body 的 assetBindings 可选以兼容旧客户端。
- PromptCompiler `neutral-text-2` 在 snapshot.entityRevisions 固定完整设定与媒体证据；rendered.inputBindings 指明实体修订、媒体版本和语义位置。旧编译器快照保持原版本与内容。

新表 asset_entities、asset_entity_revisions、entity_media_bindings、shot_asset_bindings；迁移0020/0021只追加表、范围外键、索引及不可变/状态约束。所有写入、卡追加和审计在事务内；保存失败连版本推进一起回滚。常规界面不显示UUID输入或SHA256，API和备份继续保留完整性证据。

## 范围与恢复

本包只支持项目内复用；尚无跨项目共享、复制/迁移、正式资产审批、独立造型库、结构化连续性、自动三视图生成、人物到声音版本的关联、细粒度样本授权名单或批量重生。固定参考不等于已经验证身份/服装一致，描述文字也不等于有实际媒体。

下一阶段先增加实体修订的明确审批/撤销事件及生成准入，再建设媒体 Provider、能力/工作流绑定和 ComfyUI 任务。不会以本包草稿状态冒充已批准、生成成功或完整V1。

数据库备份须与完整媒体根配套，参见 [LOCAL-MEDIA](LOCAL-MEDIA.md)。本包自动化实际验证了带实体/固定卡引用/提示词/声音样本/媒体的复制恢复；正式库不填入测试资产。回退使用匹配代码、数据库与媒体副本的新路径，不删新记录或逆向重建旧表。
