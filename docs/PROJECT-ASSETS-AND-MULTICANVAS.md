这次我又核对了 [Infinite-Canvas](https://github.com/hero8152/Infinite-Canvas?utm_source=chatgpt.com) 的画布代码，发现有两项值得直接借鉴的产品能力：

- 多参考素材聚合：多个上游图片节点可以连接到生成节点，系统收集这些参考图，再填入 ComfyUI 工作流开放的输入字段。它的部分图片编辑流程最多使用前三张参考图。
- 提示词预设与模板：可以把画布上的提示词保存到预设库，后续复用、编辑和应用，不需要每次重新输入。

我们要在此基础上做得更明确：角色图片、场景图片、参考视频和声音应当使用有名称、有类型的输入端口，不能仅凭连线先后顺序来判断它们的用途。

还有一个直接影响实施的重要事实：MiniMax H3 本身主要负责视频生成，不是通用静态图片生成模型。 ComfyUI 的 H3 工作流支持 T2V、I2V，以及独立的 R2V 多参考模式。官方 R2V 工作流支持最多 9 张参考图片、3 段参考视频和 3 段音频，但需要对应的 Ref2VA 模型和工作流，不能因为单首帧 I2V 已跑通，就默认多参考也已具备。

# Pullet Studio — 项目资产库、多无限画布与多参考生成系统设计

**状态：正式产品设计方向**

**产品基线：2026-11-06**

**参考项目：** [https://github.com/hero8152/Infinite-Canvas](https://github.com/hero8152/Infinite-Canvas)

**Pullet Studio：** [https://github.com/XMJGame/PulletStudio](https://github.com/XMJGame/PulletStudio)

## 一、产品目标

Pullet Studio 采用项目驱动的 AI 创作体验。

普通用户的主要流程：

**进入项目 → 打开无限画布 → 选择资产或粘贴提示词 → 连接生成节点 → 生成 → 对比结果 → 保存资产 → 继续创作。**

不要求创建剧本、分镜、正式镜头或复杂制作结构。

特别参考 Infinite-Canvas 的：

- 无限画布交互。
- 多媒体参考节点。
- 多节点连线生成。
- ComfyUI 自定义工作流。
- 生成节点动态参数。
- 多参考图选择。
- 提示词预设与模板。
- 生成结果回流画布。
- 素材快速导入与复用。

其源码授权限制必须遵守。参考交互和功能机制，Pullet Studio 独立实现，不直接复制未经授权的源码或资源。

## 二、工作区与项目结构

### 2.1 工作区 Workspace

工作区作为后台团队和资源管理范围继续存在。

负责：

- 团队身份与成员。
- 工作区管理员。
- ComfyUI 实例。
- 统一生成资源配置。
- 未来可共享的团队资源。
- 安全与权限。

普通单工作区用户不需要手动创建或切换工作区。系统可在初始化时创建默认工作区。

### 2.2 项目 Project

项目是用户主要感知的创作单位。

每个项目拥有：

- 独立资产库。
- 独立提示词库。
- 多个无限画布。
- 生成任务及结果。
- 项目工作流使用权限。
- 项目成员与权限。
- 导出素材。

项目支持可选内容组织，但不强制拥有剧本、分镜、章节或镜头。

### 2.3 一个项目支持多个无限画布

一个项目可以创建多个画布。

例如：

项目：盘古神话

- 角色探索画布。
- 场景探索画布。
- 开天场景画布。
- 镜头视频生成画布。
- 素材备选画布。

每个画布拥有独立布局、节点、连线和保存历史。

但画布不应建立自己的独立正式资产库。

同项目画布引用相同的资产 ID 和固定媒体版本。

一个画布生成的图片可以在另一个画布使用。

新建项目时可以提供默认主画布，也允许用户自行创建。

推荐界面：

- 项目顶部显示画布切换入口。
- 支持新建、重命名和切换画布。
- 支持画布列表、搜索和归档。
- 打开项目默认进入上次使用的画布。
- 资产库、提示词库和任务结果在同一项目中共享。

已有 Board / BoardRevision 体系必须优先复用，不得另建一个第二画布系统。

## 三、项目资产库

### 3.1 资源类型

首版以现有资产和媒体基础扩展：

| 类型    | 主要用途                   |
| ----- | ---------------------- |
| 角色    | 人物描述、参考图、多视图、服装版本、可选音色 |
| 场景    | 环境描述、主场景图、机位和光照版本      |
| 道具/产品 | 物体、产品、配件、材质与视觉参考       |
| 风格    | 统一视觉描述、示例图、正向/负向风格约束   |
| 图片    | 普通参考、定妆图、首帧、结果图        |
| 视频    | 参考视频、生成视频、候选片段         |
| 音色    | 声音身份、音色描述、授权样本         |
| 音频    | 旁白、对白、音效、背景音乐及其他音频     |

不要为了每一个类型开发独立的媒体存储服务。

底层继续复用 MediaAsset、MediaVersion、语义资产及其修订能力。

BGM/SFX 可优先通过音频素材的语义分类和标签实现，不必立即增加大量新表。

### 3.2 角色资产的特殊结构

角色节点应能引用一个角色资产，并选择当前需要使用的版本。

允许包含：

- 角色设定。
- 主形象图。
- 正面、侧面、背面图。
- 不同服装参考。
- 表情和动作参考。
- 角色关联音色。
- 可选声音样本。

角色在画布上表现为一个语义节点，但可以暴露多个输出端口：

- 主形象 IMAGE。
- 正面 IMAGE。
- 侧面 IMAGE。
- 背面 IMAGE。
- 参考图集合 IMAGE[]。
- 声音样本 AUDIO（有授权媒体时）。
- 角色描述 TEXT。

音色元数据不能直接冒充可供模型使用的音频文件。

角色没有声音样本时，AUDIO 输出不可用。

### 3.3 场景资产

一个场景可以拥有多张参考图和不同机位。

拖入画布后可以：

- 使用默认主图。
- 切换具体机位。
- 选择多个场景参考。
- 将图片连接到对应生成输入。

同一个场景资产在不同画布中可以引用不同固定媒体版本。

## 四、资源库权限设计

这是新增的正式需求。

### 4.1 默认权限

每个资产拥有归属项目 `ownerProjectId`。

默认策略：

**仅归属项目中拥有相应项目权限的成员可以查看、引用和使用该资产。**

其他项目，即使处于同一个工作区，也不能默认读取其资产。

项目中的所有画布遵守同一资源权限，不按画布重复创建授权规则。

### 4.2 指定项目共享

资产管理员可以将一个资产开放给同工作区中的指定项目。

例如：

角色资产“盘古”属于项目 A。

管理员授权项目 B 使用。

项目 B 的创作者可以在资源库中找到该共享角色，并把它拖入自己的画布。

但项目 B 不获得对项目 A 其他内容的访问权。

### 4.3 指定用户共享

可以给同一工作区内的指定用户授予资产访问权限。

即使该用户不是源项目成员，也只能访问被明确授权的资产，不能据此访问整个源项目。

用户只有在具备目标项目编辑权限时，才能将该资产用于目标项目的创作。

跨工作区、外部用户或公开链接分享不作为首版必需功能。

### 4.4 权限级别

建议最小权限集合：

| 权限        | 能力                        |
| --------- | ------------------------- |
| 查看 View   | 查看授权资产的允许公开元数据和预览         |
| 使用 Use    | 将资产作为画布与生成输入              |
| 导出 Export | 下载或打包授权原始素材               |
| 管理 Manage | 修改资产及其共享规则，限资产所有者或明确授权管理员 |

首版可以采用少量清晰权限级别，不需要设计复杂的任意 ACL 规则语言。

共享对象建议包含：

- 资源 ID。
- 资源类型。
- 源项目 ID。
- 接收方类型：Project 或 User。
- 接收方 ID。
- 授权权限。
- 授权人及时间。
- 撤销状态。

具体表结构由 Codex 结合现有数据库设计。

### 4.5 共享的是引用，不是默认复制文件

资产跨项目共享时，默认共享源资产的授权引用。

不要直接复制二进制素材，避免重复占用 NAS 空间。

如果用户需要独立修改和管理资产，可以显式执行“复制到当前项目”，创建新的资产身份及来源关系。

复制不得绕过原资产的使用和导出授权。

### 4.6 版本与撤销

共享资产引用必须固定到明确版本。

源资产更新后，目标项目可以看到存在新版本，但不能静默替换已使用的版本。

撤销权限后：

- 不能继续查询或创建新的授权引用。
- 不能继续启动使用该资产的新生成任务。
- 需要在任务真正提交远端前复查使用权。
- 历史任务仍保留安全的来源标识和审计记录。
- 已提交远端或已归档的结果按明确的数据归属规则处理，不静默删除用户历史作品。
- 撤权后的源文件预览和下载必须重新授权。

画布中失效的资产引用显示受限占位，不泄露源项目的秘密、路径、完整描述和原文件。

### 4.7 实现注意

当前代码中的实体查询、媒体预览、Board 引用和 Generation 输入验证，多处以资源的 `projectId` 必须等于当前项目为判断条件。

因此不能只增加一个“分享”开关。

必须设计统一的 AssetAccess / ResourceAccess 权限判断，并逐步接入：

- 资产列表与搜索。
- 资产详情。
- 媒体原件与预览。
- 画布引用解析。
- 生成输入绑定。
- 任务执行前检查。
- 导出。

默认拒绝未授权访问。

保留服务端授权，不使用裸露静态目录或永久公开 URL 绕过权限。

## 五、项目提示词库

正式增加 Prompt Library。

### 5.1 为什么需要

用户可以继续在 ChatGPT、Codex、其他 Agent 或外部工具中编写提示词。

Pullet Studio 的主要价值是：

- 保存。
- 检索。
- 复制。
- 插入画布。
- 复用。
- 修改版本。
- 将完整提示词固定到生成任务。

不强制调用 AI 改写提示词。

### 5.2 提示词基本结构

建议记录：

- 标题。
- 正文。
- 可选负面提示词。
- 类型标签。
- 角色/场景/风格等关联标签。
- 推荐使用的工作流。
- 原始来源说明。
- 创建人。
- 修订历史。
- 归属项目。
- 共享权限。

类型可包括：

- 角色设定。
- 角色多视图。
- 场景生图。
- 多角色合成。
- 文生图。
- 图生图。
- 图生视频。
- 多参考视频。
- 旁白。
- 音频生成。
- 通用。

类型只是筛选标签，不建立不同的提示词系统。

### 5.3 提示词库界面

支持：

- 搜索。
- 收藏。
- 标签分类。
- 最近使用。
- 一键复制。
- 一键插入画布。
- 应用到当前生成节点。
- 从画布提示词节点保存到库。
- 编辑并创建新版本。
- 查看历史版本。

“复制提示词”是最基础、最重要的操作，不需要额外确认。

### 5.4 模板与变量

首版先支持普通完整文本。

以后可以逐步引入：

- `{{character}}`
- `{{scene}}`
- `{{style}}`
- `{{action}}`
- `{{camera}}`

但不要因为变量模板功能而阻塞普通文本的保存和使用。

生成时必须保存最终解析后的实际提示词快照，而不是只有模板 ID。

### 5.5 提示词权限

默认项目私有。

后续可复用资源授权机制，开放给指定项目或用户。

提示词共享不等于分享其绑定的私有图片；跨资源引用必须分别校验权限。

应优先复用现有 Prompt Profile 或文本版本服务中可复用的能力，但不能强制将提示词绑定到正式 Shot / PromptArtifact。

## 六、无限画布的多参考生成设计

这是新版 Pullet Studio 的核心体验。

### 6.1 画布节点类型

首版建议控制在以下几类：

1. AssetNode：角色、场景、道具、风格等语义资产。
2. MediaNode：图片、视频、音频。
3. PromptNode：提示词及文本。
4. WorkflowNode：执行已配置的 AI 工作流。
5. ResultNode：图片、视频、音频结果。
6. GroupNode：分组和便签。

不要再为每种模型单独开发节点组件。

### 6.2 多参考生成

必须支持多个上游节点连接到同一个 WorkflowNode。

例如：

角色 A 的图片 → Reference Image 1

角色 B 的图片 → Reference Image 2

场景图片 → Reference Image 3

角色 A 的声音样本 → Reference Audio 1

提示词 → Prompt

上述输入再连接到 H3 R2V 工作流节点。

但不要求每个工作流支持全部输入类型。

### 6.3 有类型的输入输出端口

使用明确的数据类型：

- TEXT
- IMAGE
- IMAGE[]
- VIDEO
- VIDEO[]
- AUDIO
- AUDIO[]
- NUMBER
- BOOLEAN
- ENUM

生成节点的实际端口由 Workflow Profile 声明。

例如：

`Character A: Main Image (IMAGE)`

连接到：

`H3 R2V: Reference Image 1 (IMAGE)`

系统必须知道这个连接对应工作流 JSON 的哪个输入字段。

不能仅依赖连接的先后顺序猜测。

### 6.4 支持两种输入方式

**方式 A：画布连线**

用户拖入角色、场景或媒体节点，连接到生成节点。

**方式 B：从资源库直接选择**

用户不希望画布出现很多素材节点时，可以在 WorkflowNode 的输入区域直接选择项目资产库中的图片、视频或音频。

两种方式应该使用同一套底层输入绑定合同。

直接选择的素材必须在生成节点上清晰显示为引用卡片，不允许形成用户不可见的隐藏输入。

支持将直接引用展开为可见节点。

### 6.5 多参考输入顺序

部分模型要求参考图按照特定顺序排列。

因此 WorkflowNode 应允许：

- 查看参考素材列表。
- 调整次序。
- 移除单张参考。
- 替换参考。
- 查看每个参考对应的角色或用途。
- 显示实际传入模型的输入编号。

例如 H3 R2V 的提示词可能需要使用 `<Picture 1>`、`<Picture 2>`、`<Audio 1>` 等标签。

Pullet Studio 必须保证最终编号和提交到工作流的真实输入一致。

参考素材的“角色”“场景”“风格”等业务标签只能作为辅助说明，不能代替工作流真实端口映射。

### 6.6 画布连线与执行关系

现有 Board 连线主要表达创作关系，不具备完整生成依赖语义。

新版要明确区分：

- annotation：普通创作关联。
- input_binding：工作流输入绑定。

只有 input_binding 才参与生成参数构建。

普通连线不应自动提交 GPU 任务。

需防止无效类型、缺失输入、超量输入、自循环和无法执行的依赖结构。

### 6.7 画布版本升级

优先复用现有 Board 和 BoardRevision。

但当前 Board v1 节点和边结构不足以保存完整的 WorkflowNode 输入绑定与 ResultNode 状态。

Codex 应评估通过新增 schemaVersion 或向兼容结构扩展实现。

要求：

- 不重新解释旧 Board 的注释连线为生成输入。
- 旧画布仍可读取和编辑。
- 新画布能够保存有类型端口及绑定。
- 生成任务与画布版本关联。
- 画布关闭后任务继续运行。
- 重新打开画布后能恢复生成状态与结果。

### 6.8 结果回流

用户点击生成后：

1. 服务端创建持久化 Generation Job。
2. 生成节点显示排队或运行状态。
3. 完成后保存结果媒体。
4. 画布显示输出候选。
5. 用户可以比较、采用、入库、导出。
6. 结果节点可以连接新的生成节点继续创作。

对于已完成的任务，不应依赖浏览器进程临时存放结果。

同一任务重试或页面刷新，不能重复创建结果节点或重复归档媒体。

---

## 七、MiniMax H3 当前接入范围

现阶段优先使用已有本地 MiniMax H3，不要求同时接入大量模型。

但必须明确 H3 各工作流的实际能力。

### 7.1 H3 T2V

输入：文本提示词。

输出：视频及工作流支持的音频结果。

适合视频概念和无首帧生成。

### 7.2 H3 I2V

输入：

- 首帧图片。
- 可选尾帧，前提是对应工作流提供绑定。
- 提示词。
- 生成参数。

输出：视频。

这是当前 Pullet Studio 已有真实执行基础的方向。

### 7.3 H3 R2V

输入：

- 多张参考图片。
- 可选参考视频。
- 可选参考音频。
- 提示词及参数。

ComfyUI 官方工作流说明中，H3 R2V 最多支持 9 张参考图片、3 段参考视频和 3 段独立音频。

但 R2V 需要对应的 Ref2VA 模型权重及节点配置，不等于现有 FL2VA I2V 工作流自动支持。

实施前必须检查本机是否实际安装对应权重、节点及可执行工作流。

不自动下载大模型、不重装已有 ComfyUI、不擅自变更模型目录。

### 7.4 H3 不是静态生图的通用替代品

用户希望的角色定妆图、三视图、场景图和多角色静态合成，通常仍需要独立图像生成工作流。

因此 V1 的处理是：

- 先支持从外部导入图片。
- 正常建立角色与场景资产。
- 在画布上使用已有图片完成 H3 视频生成。
- 保留文生图/图生图工作流节点的接口。
- 当用户配置了实际可运行的图像工作流后再开放对应能力。
- 三视图生成作为可导入、可配置的工作流模板实现。

不能仅为了界面完整，将尚不可用的静态图片生成功能显示为已经可以执行。

### 7.5 音色和角色音频

H3 R2V 如果支持音频参考，可将有授权的角色声音样本或旁白样本绑定到对应 AUDIO 端口。

但要区分：

- 音色资产身份。
- 试听或参考音频。
- TTS 生成台词。
- 模型最终输出音轨。

它们不是同一个概念。

不能因为角色节点设置了音色，就默认 H3 会自动生成指定台词或精确保持角色声音。

## 八、结果与资产关系

生成结果首先属于项目和生成任务。

用户可以选择：

- 保留候选。
- 加入资产库。
- 作为现有角色/场景/道具的新媒体版本。
- 保存为独立图片或视频素材。
- 添加到其他画布。
- 导出原件。

普通媒体结果不强制创建 Shot Take。

正式镜头生产模式可以继续使用已有 Take 和审批机制。

注意：从共享资产生成的衍生结果，需要记录其来源资产 ID、固定版本及授权使用时的上下文。

### 项目内

## 十二、最低验收标准

### 场景 1：多画布

一个项目创建三张画布。

所有画布均可引用同一个角色资产。

不同画布拥有各自节点布局和保存历史。

### 场景 2：默认私有

项目 A 的角色默认不能被项目 B 查询、预览、拖入、用于生成或下载。

即使同处一个工作区也必须如此。

### 场景 3：项目共享

项目 A 的管理员将角色授权项目 B 使用。

B 可以在项目资源选择器中找到该资产，并选择固定参考图用于生成。

但 B 不能读取 A 的其他非共享资源。

### 场景 4：指定用户共享

给工作区成员 U 授权一个资产。

U 只可使用这一资源，不因此获得源项目整体权限。

撤权后不可再启动新的生成任务。

### 场景 5：提示词复用

创建一个提示词，保存至项目提示词库。

从另一张画布搜索并一键插入。

编辑提示词库的新版本，不影响之前生成任务中的固定提示词。

### 场景 6：多参考图

画布放入角色 A、角色 B 和场景图片。

连接到同一工作流的不同 IMAGE 输入。

输入端口显示明确名称、顺序和实际工作流映射。

如果工作流不支持三个输入，应明确提示不可执行，不静默忽略素材。

### 场景 7：角色音频

角色有主形象图和声音样本。

画布可以分别连接 IMAGE 和 AUDIO 输出。

工作流缺少 AUDIO 输入时不能假装成功使用声音。

### 场景 8：H3 实际生成

使用已经可运行的 H3 I2V 工作流：

- 指定首帧。
- 输入提示词。
- 提交任务。
- 关闭或刷新页面。
- 返回查看结果。
- 保存为项目素材。
- 将结果拖到第二张画布。

R2V 多参考图应使用真实 Ref2VA 工作流单独验证，不能用 I2V Mock 代替验收。

### 场景 9：历史兼容

升级后旧 Board、媒体、工作流及 Shot 仍可正常访问。

旧注释连线不会被误识别为工作流执行依赖。

## 我还有一个重要建议

不要把多角色、多场景、多声音理解为“全部连上一个 H3 节点就一定能生成正确的视频”。

真正好用的软件要分清两件事：

- 画布能表达什么：可以组合任意数量的角色、场景、参考素材和提示词。
- 当前工作流实际支持什么：由对应 ComfyUI 工作流的模型、输入端口、数量限制及运行验证决定。

比如使用 H3 R2V，角色 A、角色 B、场景可以各占一个参考图片位置，提示词明确描述各自身份和动作；如果使用已经跑通的单首帧 I2V，则先选定一张合成参考图，不能直接假设多参考图都能传进去。

这样设计的好处是：今天先用 MiniMax H3，未来换其他生图或视频工作流，无限画布、资产库、提示词库和授权系统都不用推倒重写。

我认为这版方案可以成为 Pullet Studio 下一轮开发的正式依据。
