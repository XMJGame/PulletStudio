# ADR-009：影视生产、轻量预演与后期交接边界

状态：采用。2026-11-05。用户认可不做专业剪辑器，并要求从产品、架构和实际使用评估参考建议；本决定是取舍结果，不是逐项照搬参考材料。

## 产品取舍

- 两个核心入口：生产工作台负责剧本、镜头卡、制作顺序/计划时长、生成任务、分工、Take比较/审核/选片与交付；创作画布负责参考、提示词、生成配置、结果比较与显式提交候选。共享Production Core，沿用现有Provider/Storage/多人工作区。
- 保留已验证的MediaService、FFprobe/FFmpeg、媒体预览、Timeline不可变片段快照、Worker恢复与低清预演，不删表、不重写历史。预演用于顺序/缺片/时长/完整性和叙事节奏检查，不把它扩展为完整剪辑界面。
- 停止新增多轨剪辑、转场、关键帧、调色、特效合成和专业混音。声音生成/导入/版本管理属于素材生产，字幕来源和SRT交付属于交接，不能因取消剪辑器一并取消；但已有对白或旁白文字不等于准确字幕时间码。
- 当前按真实数据交付：先把已批准选片原件、CSV镜头清单、制作说明与JSON清单装进同一个固定包。现阶段只有单镜头所选Take，不能声称已能同时附加独立旁白/BGM/SFX和字幕。后续补明确的附件来源/角色/时间码/审批/权限合同，再接入已有音频/SRT；不自动按文件名或对白猜分类/时间。
- 目录以媒体类型和实际存在内容组织。复用的原件只存一份，多个镜头通过清单引用；不为了看起来齐全创建空文件、空目录或虚构PDF/SRT。示例作品名不进入代码。ShotList列出全部镜头、相对路径、Take/审批/卡版本、计划与实测时长，二者不混同，不生成看似精确的剪辑时间码。
- OTIO/FCPXML后置到实际编辑器与版本的兼容性验收，不阻塞V1，也不承诺一个文件通用导入所有软件。完整项目重导入与编辑器工程交接分别设计。

## 已有代码审计

| 位置 | 现状与处理 |
|---|---|
| production/、prompt/、generation/、assets/ | 现有业务核心、资产/Take审核/选片、归档与预览，全部保留 |
| timeline/timeline-contract、service、controller | 既有整数毫秒顺序快照和预演接口，无多轨、转场、关键帧编辑器，保留兼容 |
| timeline/animatic-renderer、worker、animatic-worker CLI | 低清渲染、原声keep/mute、租约和归档，保留为可选审核能力 |
| Web AnimaticDialog | 表单式片段顺序/入点/时长，不是NLE轨道UI；保留，停止扩大剪辑能力 |
| exports/ | 文本分镜与媒体ZIP可复用，优先增量标准交接，不另建一套导出队列或数据库 |
| 上一轮未提交的声音/字幕扩展 | 已撤回，未迁移数据库；没有正式历史需要清除 |

## 实施顺序

先交付一个小包：标准后期交付目录＋CSV/制作说明＋旧包字节兼容。随后继续ADR-008的G0画布原型和G1引用看板；E的分工/批次预检/评论通知持续按依赖推进，不因剪辑范围收缩而停止。声音/字幕附件按实际生产需求插入，不成为画布前置条件。

本ADR优先于MASTER-PLAN、技术蓝图及旧路线中“真正多轨编辑后续”“基础多轨”“复杂时间线”的安排。更新这些工作文档的冲突表述；原有实现与历史测试证据保留。
