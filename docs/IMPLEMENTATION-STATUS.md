- 当前工程是 React/TypeScript/Vite + NestJS 11 + Drizzle + better-sqlite3，已有业务代码，继续保留。现有 CSS、对话框和权限组件复用，不为引入 UI 库改写。
- 初次审计为 13 张业务表/6 次迁移；P2-B1 后为 24 张业务表/14 次迁移，已增加来源、文本连接/模型、分析任务/草案、人工审核、完整卡历史及来源关联。WAL、外键、busy_timeout、在线备份及 API/Worker 并发迁移启动已测试；实库 integrity=ok、foreign_key_check=[]，未用真实数据造样例。
- 最新 `npm test` 70/70（含容器）；Edge 全流程 1/1、类型/格式/构建通过，涵盖独立 Worker 与模型 Mock、队列恢复、人工审核/原子采纳、制作卡历史及手机/双窗口界面。真实模型联调未完成。
- 2026-11-05 按用户要求初始化 Git，并配置远端 `https://github.com/XMJGame/PulletStudio.git`；CI 配置已添加，远端执行结果以 GitHub Actions 为准。独立文本 Worker 已实现并在本机启动；Compose/媒体存储尚未实现。packages/contracts 的旧媒体 Provider/Storage 仍只是草案；实际 TextProvider 端口在 API providers 模块独立实现。

DOCX/PDF adapters 作为 P1 的后续增强，在 TXT/MD 闭环稳定后按需要插入，不阻塞 P2 文本 Provider 与 AI 分镜。复杂导演模板同样渐进扩展，先保证通用镜头意图及必要字段，不先做大规模模板库。

## P2-B1 实施合同（已完成基础范围，编码前记录）

- 实现原始模型草案上的人工候选编辑、整份拒绝/重开和采纳。原 analysis_proposals 不改；以 proposal_reviews 当前指针 + proposal_revisions 追加修订/决定，原始草案为虚拟 v0，读操作不新增记录。
- 候选顺序/数量本阶段固定，编辑已有镜头卡字段与范围内原文引用，所有写入 expectedVersion；草案编辑用项目编辑权限，拒绝/重开/采纳用独立 review 权限（工作区管理员、项目管理、REVIEWER），不会给审核者通用镜头编辑权限。
- 采纳整份候选到项目直属或指定制作单元，须明确确认计划时长（沿用现有 1–3600 整数秒镜头计划，不冒充实际声音测量）。事务原子写入正式 Shot、完整 shot_card_revisions、script_spans、shot_script_spans、proposal_adoptions、审核版本及审计；编号依旧后台生成。任何失败全部回滚，重复相同采纳返回既有映射。
- 修订原文/项目设定较分析快照更新时显示差异警告并须明确确认；不自动重定位来源。已采纳草案不再编辑/拒绝/重开，后续修改正式镜头追加制作卡版本并保留采纳快照。
- 旧镜头编辑接口保留：已有完整制作卡的镜头，修改画面/运镜/对白/时长/方式时同步追加卡版本；其他字段和来源保留。手动旧镜头不虚构完整卡。支持查看制作卡、原文及历史版本，后续 PromptCompiler 直接使用该版本。
- API 新增 /proposals/:id、/versions、/shots/:index、/reject、/reopen、/accept；/shots/:id/card 及版本读取。UI 加候选编辑、审核确认/目标单元、拒绝理由、修订历史及正式镜头制作卡查看。
- 增量表/索引/约束/不可变触发器，迁移前在线备份，旧表/原文/模型结果不重建。测试先补角色矩阵、来源完整性、409、重放/并发/回滚、时长未确认、旧来源确认、审核不可逆、正式卡续写、撤权/回收站、重启与浏览器手机/双窗口流程。
- 本轮只交付 P2-B1 人工门禁，Story Bible、幕场分层任务、单份候选的新增/删除/重排、Take 审核和声音实测后续实施；不将其宣称为完整 P2-B 或完整生产闭环。

## P2-A 实施合同（已完成基础范围）

- 增加工作区文本连接（通用 Chat Completions compatible adapter），名称/模型/端点/JSON 输出模式/输出上限/超时分别配置；不指定某个厂商或默认模型。新增端点由已加入工作区且有工作区管理权限的实例管理员批准，私有地址单独明确授权；普通成员不可配置凭据。
- Provider 凭据以 AES-256-GCM、随机 IV、connection/workspace AAD 加密保存，API 只返回 hasApiKey；master key 由本机 setup 写入忽略的 .env，不打印。保持既有初始化密钥和用户数据。
- 网络只允许已批准连接；公网默认 HTTPS，DNS 解析检查所有地址并固定实际连接 IP，拒绝重定向和 metadata/link-local 地址；私有/本机连接必须显式批准。请求、响应、超时均有界，不返回供应商原始错误或密钥。
- 追加 text_connections、text_model_profiles、analysis_runs、analysis_proposals，连接/模型分表。任务冻结连接版本、剧本修订、设定和原文范围，Idempotency-Key 防重复创建。单次原文最多 8,000 UTF-16 单元，按稳定来源块拆分；大篇不整稿一次提交模型。用户输入的上下文摘要为明确选择的附加上下文，不自动发送其他原文。
- 独立 Node Worker，数据库事务领取/租约/心跳；发送前重新检查成员、项目状态和连接版本。准备阶段失租可恢复，已提交后失租/断线进入 NeedsReconciliation；仅明确 429 可按 Retry-After 自动重试，5xx 和不确定提交保守转人工核实。显式取消为停止跟踪，不虚称远端已取消；再次排队须确认重复调用风险。
- TextProvider 输出经过 Zod、来源块 ID/哈希及范围校验，保存为待审核草案；不改正式剧本/单元/镜头。提供提交、查看任务/来源草案、取消、人工核实后重排入口，人工采纳在 P2-B 实施。
- UI 增加文本连接配置和 AI 分镜分析视图，显示发送范围、连接/模型、队列/Worker 状态、结果及真实错误分类；没有模型不能显示生成成功。后台运行不阻塞页面，轮询数据库状态。
- 修改 API/providers/analysis、worker CLI、setup/config、增量迁移、Web 组件/类型、独立 HTTP Mock 与 E2E、CI 和使用/恢复文档。迁移前备份，不重建旧表，不动外部 ComfyUI。
- 测试覆盖加密/脱敏/端点授权/SSRF/拒绝重定向、租户权限、幂等冲突、结构/来源校验、429/5xx/断线、租约竞争/进程重启/陈旧结果、取消/离职/回收站和真实 Worker 子进程、UI 连接/分析/草案/手机布局。真实付费模型留到用户配置后的联调，Mock 通过不等于真实服务验收。

## P1-B 实施合同（已完成基础范围）

- 追加 Project 的 workFormat、narrativeMode、targetDurationSeconds、directorNotes；四轴中的视觉风格复用原字段，制作方式属于 Shot，追加 technique。模板只提供可修改的起始值，不能决定模型/工作流或覆盖内容。
- ProductionUnit 通过现有 episodes 表增量扩展 unit_type、parent_id、outline、target_duration_seconds 实现；统一结构服务将其映射为 Unit，不新建第二套分集数据。旧 API 继续只列 episode 类型，旧 ID/编号/镜头外键保留。详见 ADR-004。
- 使用内部 project_root 行承载直接项目镜头的既有外键与编号计数；对外 unitId=null，不出现在制作树或分集列表。新镜头无需用户先创建分集，不改写旧镜头。
- API：GET/POST /projects/:id/units、GET/PATCH /units/:id；GET/POST /projects/:id/shots（unitId 可空）；POST /projects/:id/settings-impact。列表分页，结构写入沿用编辑权限、版本条件与事务，拒绝跨项目父链及循环；新字段和层级数据库约束采用增量迁移/触发器。
- 设置变更有实际已有剧本/结构/镜头时，返回影响范围并要求 acknowledgeImpact，再按项目版本锁保存；不自动改变已有结构/文本/镜头。未知或过期配置仍拒绝。
- UI：项目起始模板/格式/叙事/目标时长/导演说明；项目设置影响确认；独立制作结构视图和单元创建/编辑/项目直辖镜头。原分集故事板保持可用，复用镜头编辑组件。
- 迁移前在线备份。测试先补项目默认/模板组合/影响确认、编号并发与兼容、父链越权/循环/排序、根镜头、只读/回收站/409/重启、旧库保留与浏览器桌面/手机。无新模型依赖，不伪称已完成 AI 分镜。
- 本阶段不做正式版本化 DirectorProfile/ProductionPlan，不实现单元删除和跨单元镜头移动（保持既有编号作用域），后续在审核及制作计划阶段增量补齐。

## P1-A 实施合同（已完成）

- 修改：`apps/api/src/scripts/*`、DB schema/增量迁移、`apps/web/src/components/ScriptWorkbench.tsx`、新增导入/来源组件、类型、API/E2E 测试、使用与变更文档。
- API：现有 `/projects/:id/script` 保存/历史不改路径；新增 `/import`（file/paste、kind、expectedVersion）、`/lock`、`/unlock`、`/versions/:version/source`、`/versions/:version/spans`。
- Schema：scripts 追加锁状态与独立锁版本；新增不可变 script_sources，关联具体历史修订。原始小文本上限 180,000 字节、正文保持现有 60,000 UTF-16 单元上限；来源在 SQLite 中保存原始 BLOB，作为有界文本证据库，不是媒体 Storage 实现。P3 才引入通用媒体存储，届时通过校验迁移来源并保留 ID，不让 UI 依赖存储位置。
- UTF-8 TXT/MD 首批上线，保留原始字节、BOM/换行；解析只去正文开头 BOM，不改换行、不渲染 Markdown。其他编码/格式明确拒绝；DOCX/PDF 不伪装支持。
- 锁定保护当前定稿，项目管理权限明确锁定/解锁，编辑权限保存/导入；旧版本永远不可变。锁定不增加文本版本，独立 lockVersion 防并发。
- 段落定位以不可变 revision ID + UTF-16 start/end + SHA256 为稳定证据，逐行保留全部字符并分页。先用纯派生定位 API；Proposal 接纳时再持久化实际使用的 ScriptSpan，避免一次创建所有未来业务表。
- 增量迁移前在线备份；不删除/重建已有表，不改用户正文或编号。回退用备份复制至新 DB 路径，不倒删生产记录。
- 测试先补：文件字节/哈希往返、CRLF/emoji/BOM、错误编码/超限、导入版本冲突、锁定的全部写入口、管理/编辑/只读/跨租户、重启、来源分页、浏览器导入预览/确认/冲突输入保留/手机与键盘。

## 遗留与需要外部配合的事项

- 正式验收全文剧本尚未由用户导入；不以概要代替，不在业务代码中植入特定作品。自动化用虚构通用对白、广告与 Unicode 资料。

- 目前不承诺分布式 GPU、S3、生产部署、80 分钟性能；所有阶段逐一记录实际测试结果。
- 核心框架更换、破坏性数据迁移或重要需求冲突，先说明并等待用户确认。普通实现细节自行决定。
