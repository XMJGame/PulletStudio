# ADR-005：团队生产内核与兼容增量

状态：采用。2026-11-05。依据用户明确采用团队级技术规格。

V1 面向团队和个人共用的 Production Core，继续使用 NestJS/React/Drizzle/SQLite、现有身份/权限、episodes 制作树、正式 Shot 和不可变来源/审核历史。画布、Recipe、Agent 均通过同一业务 API 操作，不能持有另一份镜头/资产真相或直接写数据库。权限角色与制作岗位分离，任务指派不授予访问权。

实施依赖为文本交付→存储/媒体与语义资产→生成/Take→团队批次/审核→声音/时间线→画布/受控扩展；部署、备份与 CI 随阶段完善。主技术栈和现有物理表不为规格示例命名而改造。Python 仅在确有算法需要时作为隔离 Worker，主业务和权限仍由 Node 服务负责。颜色/布局为参考，优先可读、键盘、小屏与失败输入保留。

现有 shot_card_revisions 的 source_proposal_revision_id 为 NOT NULL，无法表达真正手动来源。保留原表、外键及不可变触发器；新增 shot_card_editions 只存后续人工完整卡修订，来源 Proposal 可空。两表由共享卡服务合成一条以 Shot.version 为准的历史，跨表版本唯一触发器防重复，不迁移/复制旧快照。既有 AI 采纳仍写原表，人工编辑统一写新附表。未来若合并物理历史须独立迁移验收。

新 PromptProfile 采用项目级追加修订，PromptArtifact 固定卡 ID/版本、项目设定快照、来源和 Profile 修订；模型/媒体未实现能力明确警告，不假造引用或生产就绪。无配置模型也可编译手工提示词。媒体 ModelProfile、Director/Style 独立版本和真实资产引用在后续消费者具备后增量实现。

外部项目先看许可和结构，只学习所需机制；本阶段独立实现，不引入第三方影视源码或画布/AI 框架依赖。不能因参考目录内容而执行脚本、付费调用或擅改用户 ComfyUI。
